Por que multi-casamento

Um sistema, vários casais

Um site feito para um único casamento morre depois da festa. A mesma base atendendo vários casamentos vira produto: cada casal entra com seu endereço, sua identidade e seus convidados — os dados de um nunca enxergam os do outro.

  • Endereço próprio por casal (vows.com.br/ana-e-rafael)
  • Identidade própria — cores, fotos, textos
  • Dados isolados — cada casal só vê os seus convidados
  • Planos — cobrança por casamento ou assinatura
  • Novo casamento no ar em minutos, sem refazer nada

Como isso é construído

Arquitetura multi-tenant: uma base de código e um banco com os dados separados por casamento. É o que permite escalar sem virar dez projetos diferentes para manter.

Evolução do projeto

O mesmo código vira app

Com Capacitor, o site que já construímos é empacotado como aplicativo nativo para Android e iOS — sem reescrever nada e sem manter dois projetos.

Mesmo código→Capacitor→App nas lojas

E como a base é multi-casamento, um app só atende todos os casais — cada convidado entra no casamento dele.

O que o app ganha

  • Notificação push — transfer, mudança de horário, contagem regressiva
  • Funciona offline — programação e mapa sem sinal
  • Ícone na tela do convidado, não some no meio das mensagens
  • Rota nativa — abre direto no Waze/Maps
  • Galeria colaborativa — convidados enviam as fotos do dia
